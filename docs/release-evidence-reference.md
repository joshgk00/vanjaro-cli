# Public release evidence reference

These Draft 2020-12 schemas describe exchange shapes; schema-valid data is not
proof that evidence was observed or that a gate passed. Canonical shape-only
examples live in [`release/examples`](../release/examples/README.md).

| Contract | Producer → consumer | Measured fields | Derived or bound fields | Verifier recomputation |
|---|---|---|---|---|
| [`ReleaseContract`](../schemas/release/release-contract.schema.json) ([example](../release/examples/release-contract.json)) | Release operator → release verifier | Evaluation date and selected artifact inventory | Candidate ID, relative paths, and supplied SHA-256 bindings | Resolves only repository-relative references, hashes every referenced file, enforces source-kind completeness/uniqueness, and evaluates all gates fail closed. |
| [`TestPolicy`](../schemas/release/test-policy.schema.json) ([example](../release/examples/test-policy.json)) | Repository maintainer → test runner and release verifier | Governed command, source globs, deselection allowance, required control node IDs | Schema version | Expands source globs and control groups, and treats the tracked policy as the governing set. |
| [`TestEvidenceReceipt`](../schemas/release/test-evidence-receipt.schema.json) ([example](../release/examples/test-evidence-receipt.json)) | Authorized governed test runner → release verifier | Collected/passed/failed/error/deselected counts and collected node IDs | Node-ID and source-tree SHA-256 values | Rebuilds the source inventory and its digest, recomputes the node-ID digest, checks counts/allowance, and—when execution is authorized—requires a fresh run to match. |
| [`ControlEvidenceReceipt`](../schemas/release/control-evidence-receipt.schema.json) ([example](../release/examples/control-evidence-receipt.json)) | Reliability test recorder → release verifier | Passing test IDs by control category | Test-receipt SHA-256 binding | Hashes the test receipt and requires every category to exactly match the policy IDs and verified collected nodes. |
| [`ProjectQualityEvidence`](../schemas/release/project-quality-evidence.schema.json) ([example](../release/examples/project-quality-evidence.json)) | Project evidence recorder → release verifier | Integer numerator/denominator observations for four quality measures | Candidate/project/source bindings; ratios are intentionally absent | Divides each numerator by its denominator, applies per-source thresholds, and aggregates the three required source kinds. |
| [`ProjectEffortEvidence`](../schemas/release/project-effort-evidence.schema.json) ([example](../release/examples/project-effort-evidence.json)) | Operator time recorder → release verifier | Session IDs, operator IDs, and measured minutes | Candidate/project/source plus protocol and policy digest bindings | Hashes protocol/policy files, sums baseline/current minutes, computes reduction, rejects non-finite totals, and requires at least 60%. |
| [`ProjectReleaseReceipt`](../schemas/release/project-release-receipt.schema.json) ([example](../release/examples/project-release-receipt.json)) | Project release workflow → release verifier | No independent measurements; it is a binding receipt | Candidate/project/source and four artifact SHA-256 values | Hashes the manifest, maintenance scorecard, quality evidence, and effort evidence; then checks identity/fingerprint consistency and downstream readiness. |
| [`LiveEvidenceReceipt`](../schemas/release/live-evidence-receipt.schema.json) ([example](../release/examples/live-evidence-receipt.json)) | Authorized portal observer/workflow → embedding caller's trusted live verifier and release verifier | Portal/version observation, time/validity, capture dimensions, smoke statuses, cleanup result | Project/publish/launch fingerprints, artifact digests, and attestation reference | Validates identity and validity, hashes and decodes PNG captures, checks required dimensions/chunks/pixels and the complete smoke matrix, binds fingerprints, and delegates real-portal trust to the supplied live verifier. |
| [`LiveAttestationReceipt`](../schemas/release/live-attestation-receipt.schema.json) ([example](../release/examples/live-attestation-receipt.json)) | Named authorized operator → trusted live verifier and release verifier | Operator observation statement, portal identity, time, and routes | Capture SHA-256 map and candidate/project/source bindings | Hashes capture bytes, compares all three digests, requires complete capture/smoke route maps, and matches portal/time/project identity to the live receipt. |

Generation is deterministic: run `python tools/generate_release_schemas.py`, or
use `--check` in verification jobs to report drift without writing files.
